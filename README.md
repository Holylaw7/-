# 长江雨课堂 · 自动刷课助手

针对 **长江雨课堂**（`changjiang.yuketang.cn`）的篡改猴（Tampermonkey）用户脚本。
实现三个目标：**自动跳转下一节**、**锁定 2 倍速**、**切换页面 / 最小化后仍然后台播放**。

> ⚠️ 仅供个人学习辅助使用。脚本只做「自动播放 + 自动翻页」，**不会伪造学习进度**，
> 所有进度仍由雨课堂服务端按真实播放时长记账。请遵守你所在学校的课程规定。

## 二、使用

打开课程目录页（`/v2/web/studentLog/教室号`）或任意视频播放页，
脚本**默认自动开始**，右下角面板可随时干预。

| 操作 | 快捷键 | 说明 |
|---|---|---|
| 开始 / 停止 | `Alt + S` | 也可点面板按钮 |
| 收起 / 展开面板 | `Alt + Y` | |
| 切 1x / 2x / 3x | `Alt + 1 / 2 / 3` | 也可点面板上的倍速分段控件 |

面板开关项：

- **后台防暂停**：勾选后切标签页 / 最小化都不掉线（核心功能，默认开）
- **自动跳转**：一节看完自动进下一节（默认开）
- **静音**：后台自动播放的前提，浏览器禁止非静音自动播放（默认开）
- **快进到结尾**：剩余不多时直接跳到末尾加速刷完（**默认关**，见「已知限制」）

面板底部「运行日志」会实时显示：当前小节、进入/完成、拦截统计（事件数 / pause 数）。

## 三、工作原理

### 1. 自动跳转

**首选（真站实测可靠）：接口驱动，不点卡片**

```
GET /v2/api/web/logs/learn/<教室号>?actype=-1&page=N&offset=20&sort=-1
```

1. 在课程目录页分页拉全列表，从 `data.activities[].content.leaf_id` 拿小节 id
2. 按 `leaf_id` 排序，跳过非视频（`type≠17`）与已完成项
3. 直接 `location.href` 跳到 `/ai-workspace/lms-graph/<教室>/video/<leaf_id>`

> 为什么不点卡片：站点的点击处理器校验鼠标悬浮状态（`hasMouse`/`mouseTarget`），
> 合成事件的坐标是 0 会被判定为无效点击而忽略。

**兜底（接口不可用时）**：DOM 解析 + 点击卡片，并记录「点了没进去」的小节，
后续 30 分钟内不再选它（避免卡死）。

**播放页找下一节**（按可靠性排序）：
1. 播放列表（接口拿到的 leaf_id）→ 直接跳 URL
2. 页面的 `data-next-leaf` 提示属性
3. 站点自己的「下一个知识点」按钮（最后一个时为 disabled）
4. 侧边目录里当前项的下一个

**完成判定**同时看 4 个信号：站点标记（`.rate-detail .text`）、进度百分比、
接口返回的 `watch_progress`、媒体播放位置（`ended` / 临近结尾）。

脚本通过**被动拦截**站点自己的 `fetch` / `XMLHttpRequest` 响应来读取进度与章节结构，
只主动调用课程列表接口（只读，不修改任何数据）。

### 2. 2 倍速

**脚本自己点击播放器自带的倍速菜单**，走站点自己的事件处理：

1. 找到 `<xt-speedbutton class="xt_video_player_speed">` 内的 `2.00X` 选项
2. 把折叠的菜单临时设为可见（否则元素尺寸为 0）
3. 派发完整鼠标事件序列（`mousemove`→`mouseover`→`mousedown`→`mouseup`→`click`），
   并显式带上真实 `clientX/clientY` 以通过站点的悬浮校验
4. 立即恢复菜单样式

这样**播放器内部变量 + 界面显示 + `video.playbackRate` 三处会一起变成 2x**。
实测结果：`media.rate=2  界面=2.00X  内部值=2`。

若菜单点击连续两次无效，且外部「倍速点击桥」可用（`_tools/speed-bridge.js`），
则改用 CDP 真实鼠标输入完成点击；两者都不可用时如实告知，**不做会被站点回滚的偷偷改值**。

判据只看 `media.playbackRate`：播放器界面标签会被站点周期性刷回 `1.00X`，
那是它自身的显示行为，不代表倍速没生效。

### 3. 后台播放（关键）

雨课堂判定「你在后台」有四类手段，脚本在 **document-start**（早于站点脚本注册监听）
就把它们全部封堵：

| 站点手段 | 脚本对策 |
|---|---|
| 监听 `visibilitychange` / `blur` / `pagehide` / `freeze` | 包装 **`dispatchEvent`**（真正的执行点）：这些事件被直接吞掉，站点监听器一个都收不到。即使监听器是在脚本注入**之前**就注册好的，同样收不到 |
| 读 `document.hidden` / `visibilityState` | 定义成不可配置的假属性，恒为 `false` / `'visible'`，站点无法覆盖 |
| 调 `document.hasFocus()` | 遮蔽为恒返回 `true` |
| 自己调 `media.pause()` | 接管 `HTMLMediaElement.prototype.pause`，非脚本自身的调用直接忽略 |
| 长时间无鼠标移动 → 弹「还在吗」遮罩 | 合成 `mousemove` / `keydown` + 自动点「继续观看」 |
| 后台把倍速压回 1x | 由倍速锁定的四重保险接住 |

外加 500ms 保活循环：静音 + 续播 + 倍速校正 + 关弹窗。

**为什么拦在 `dispatchEvent` 而不是 `addEventListener`**：只在 `addEventListener`
上做拦截，只能挡住「之后」注册的监听器；而仿真与实测都表明，站点往往在很早的阶段
（脚本注入前）就注册好了切屏监听。把屏障放在 `dispatchEvent`，无论监听器何时注册都收不到事件。

**自带自检**：脚本启动 1.2 秒后会做一次自证 —— 先确认「原生投递能送达监听器」，
再确认「经过包装层的事件无法送达」，两项都符合才判定守卫有效。
结果会写进面板的「复制诊断信息」里（`事件拦截自检` 一行）：

```
guard      : active=true blockedEvents=1 blockedPause=0 fakeReads=50
事件拦截自检: 通过（切屏事件无法送达站点监听器）  原生投递可达=true 拦截后可达=false
站点切屏监听: visibilitychange, blur
```

## 三·B、在真实站点上实测到的关键事实（v1.0.3）

下面每一条都是 2026-10 用 CDP 连真实 Edge、在已登录的真实课程页上 **实测** 得出的，
沙盒环境复刻不出来 —— 也是 v1.0.3 修掉的问题。

### 真实页面结构

| 项目 | 实测结果 |
|---|---|
| 播放器位置 | `lms-graph/.../video/...` 页面里，**就在顶层文档**，没有 iframe |
| 但目录页有 iframe | `/v2/web/studentLog/...` 是外壳，内容在 **`/pro/lms/<sku>/<教室>/studycontent` 的 iframe** 里 |
| `<video>` 的 id | 形如 `1790861333124_4d849969d6...`，**每次加载都变**，不能拿 id 做选择器 |
| 学习进度元素 | **`.rate-detail .text`**（值可能是「已完成」或「完成度：0%」）；另有 `.nav-progress .progress-num` =「完成度 100%」。**没有** `.progress-wrap` |
| 下一节按钮 | 文字是 **「下一个知识点」**，容器 `.nav-footer .nav-next`；到最后一个知识点时带 `.is-disabled` 且文字变「暂无」 |
| 倍速菜单 | `<xt-speedbutton class="xt_video_player_speed">` → `<xt-speedvalue class="xt_video_player_common_value">1.00X</xt-speedvalue>` + `<xt-speedlist class="xt_video_player_common_list_wrap">` → `<ul><li data-speed="2" keyt="2.00">2.00X</li>…`，**折叠时 `display:none`** |
| 倍速菜单标签复用坑 | `document.querySelector('xt-speedlist')` 会命中别处的 `<xt-volumewrap>`；必须用真实 class 或限定在按钮内部 |

### 后台守卫在真站上确实有用

```
守卫         : active=true 拦截事件=1 拦截pause=3
拦截自检     : {"rawDelivered":true, "blockedDelivered":false, "ok":true}
站点监听     : ["visibilitychange","blur"]
守卫备注     : ["拦截站点写入 onpagehide","拦截 pause()：VIDEO","拦截 pause()：VIDEO","拦截 pause()：VIDEO"]
```

真站**确实注册了** `visibilitychange` 和 `blur` 监听，也**确实主动调用过 3 次 `media.pause()`**——
全被脚本拦下。

### 倍速：一个必须说清楚的细节

- 直接设 `video.playbackRate = 2` **真的会 2 倍速播放**（实测播放位置每 2 秒前进 4 秒）
- 但播放器界面的「1.00X」渲染的是它**自己的内部变量**，不会跟着变
- 该内部变量在 `<player 实例>.options.speed.value`；**改它界面也不会更新**（播放器不是响应式渲染）
- 倍速菜单是 hover 展开的，而**合成 MouseEvent 不触发 CSS `:hover`**，
  所以在脚本里点不开菜单（CDP 真实鼠标输入在自动化环境下也没能稳定展开）
- 但直接改 `<xt-speedvalue>` 的文字**不会被播放器覆盖回去**（实测等待数秒仍保持）

→ 所以 v1.0.3 的策略是：**媒体倍速由 `playbackRate` 保证，界面文字由脚本同步**，
两者都会是 2.00X。实测日志：

```
0s  running=true phase=next 65%  【2.00X】  已完成(临近结尾)   ← 界面已同步
```

另外顺手修掉一个**自己造的 bug**：早期版本在巡检里无条件执行 `playbackRate = 2`，
**给 playbackRate 赋相同值也会触发 `ratechange` 事件**，于是 6 秒内伪造出 44 次事件、
把"校正次数"灌到 157。现在只在值真的不同时才赋值。

## 三·C、真实站点验证结果（v1.1.0）

以下全部是 2026-10 在你的**真实已登录环境**（Edge 154 + 长江雨课堂）里实测得到的。

### 核心突破：不点课程卡片，改用数据接口导航

**发现的问题**：脚本原本靠「点击课程卡片」进入小节，但在真站上**点了没反应**，日志表现为
`进入第 N 项：xxx` 之后 `等待超时：进入播放页`，然后永远卡在同一节。

**根因**（[油猴中文网有同题讨论](https://bbs.tampermonkey.net.cn/thread-5108-1-1.html)）：
雨课堂的卡片点击处理器会先校验「鼠标是否真的悬浮在目标上」：
```js
changeHasMosue: function (t, e) { this.hasLeftMouse = t, this.mouseTarget = e || null },
goDetail: function (e) {
  var s = e.target;
  if ((this.hasMouse || this.hasLeftMouse) && this.mouseTarget == s) { ...跳转... }
}
```
合成事件的 `clientX/clientY` 默认是 0，`hasMouse` 判定为假 → **点击被直接忽略**。
（伪造坐标的 mousemove、CDP 真实鼠标点击、甚至直接调 Vue 方法，实测均无效。）

**解决**：改为从接口拿 `leaf_id`，**直接跳 URL**，完全不碰卡片。实测可用的接口：

```
GET /v2/api/web/logs/learn/<教室号>?actype=-1&page=N&offset=20&sort=-1
→ data.activities[].content.leaf_id   ← 小节 id
  data.activities[].title             ← 小节名
  data.activities[].type              ← 17=视频 16=图文 19=作业 9=通知
  data.has_more                       ← 分页
```

`leaf_id` 数值即为课程顺序。实测一次拿全 **80 个小节 / 5 页**。现在脚本在目录页会：

1. 调该接口分页拉全课程列表（失败才退回 DOM 解析）
2. 按 `leaf_id` 排序，取下一个 `type=17`（视频）且未完成的
3. **直接 `location.href` 跳到播放页**

### 倍速：脚本自己点播放器菜单，无需任何外部工具

```
[刷课助手] 已点击播放器倍速菜单（目标 2x），等待生效…
[刷课助手] 倍速已通过播放器菜单切到 2x
实测: media.playbackRate=2   播放器界面=2.00X   站点内部值=2   ← 三处同步
```

做法：把播放器折叠的倍速菜单**临时设为可见** → 对 `2.00X` 选项派发完整的鼠标事件序列
（带真实坐标，满足站点的悬浮校验）→ 立即恢复样式。走的是站点自己的事件处理，
内部变量/界面/媒体会一起更新，不留「被外部改写」的痕迹。

### 完整链路实测结果

```
✓ 脚本通过接口拿到了课程列表  — 课程列表获取完成：共 80 项（5 页）
✓ 自动从目录页进入视频页（未点击卡片）
✓ 自动设置 2 倍速  — rate=2 界面=2.00X
✓ 拖进度条到结尾后判定本节完成  — 本节完成
✓ 自动跳转下一节  — <小节A> → <小节B>
✓ 连续自动跳转  — 连续 4 个小节自动推进
```

### 后台守卫在真站的效果

```
守卫: active=true 拦截事件=1 拦截pause=3
拦截自检: 原生投递可达=true, 拦截后可达=false  ✓
站点监听: visibilitychange, blur
守卫备注: 拦截 pause()：VIDEO  ×3      ← 真站确实在调 pause，被拦下了
```

### 关于「进度条拖到结尾」

雨课堂的完成度是**服务端按真实播放时长记账**的，所以拖进度条**不会**让进度立刻变 100%。
脚本对此的处理是：

- 若拖到结尾且站点已标记完成 → 立即判定完成并跳下一节（实测通过）
- 若站点还没标记完成 → 继续正常播放，直到服务端回传完成

所以**不建议把拖进度条当作提速手段**，正常 2 倍速播放才是可靠路径。

## 三·D、自动播放被拦截（v1.1.1 修复）

**现象**：进入播放页后视频停在原地不动，面板日志反复出现「自动播放被拦截」。

**原因**：浏览器的**自动播放策略**。没有「用户手势」时，未静音的 `play()` 会被拒绝
（`NotAllowedError: play() failed because the user didn't interact with the document first`）。
站点自己的播放器也需要一次用户交互才会开始播放。

**旧实现的缺陷**：脚本每 500ms 无条件重试 `play()`，失败就记一次数——
既无法成功，也不会因为用户后来点了页面而恢复，只是不断刷日志。

**现在的行为**：

1. 播放前**强制静音**（静音是自动播放策略放行的条件之一，同时满足后台播放需求）
2. 被 `NotAllowedError` 拒绝时，标记为「自动播放被拦」，**停止无效重试**
3. 面板显示醒目提示：*「浏览器拦住了自动播放：请在本页面任意位置点一下」*
4. 在 `document-start` 阶段监听 `pointerdown / mousedown / keydown / touchstart / wheel / click`，
   你点一下之后**立刻自动恢复播放**，整段课程后续都不再需要点击
5. 同时读取 `navigator.userActivation.hasBeenActive`，若浏览器认为页面已激活
   （例如从上一页接力过来），则直接正常播放，不打扰你

> 诊断信息里新增了 `autoplayBlocked` 与 `userGesture` 两个字段，便于排查是哪一种情况。

## 三·E、静音：默认关闭（v1.1.2 调整）

**背景**：静音是浏览器自动播放策略的豁免条件之一（「有用户手势」或「已静音」二者之一即可自动播放），
早期版本因此默认静音，以换取免交互自动播放。

**真站实测发现的问题**：站点会**反复取消静音**——约每 2 秒一次，16 秒内试了 50 多次。
早期实现为了保住静音，在属性层拦截了站点的 `muted` 写入（静音锁）。但那种持续对抗：

- 站点每次想调音量都被挡回去，行为异常；
- 拉锯本身可能被站点的异常检测注意到。

**现在的做法**：

- **脚本默认不静音**（`CFG.mute = false`），也**不做任何音量/静音干预**；
- 想安静时用浏览器自带的**「使标签页静音」**（右键标签页），比脚本对抗干净得多；
- 需要免交互自动播放的用户，可在面板勾选「静音」——此时脚本只按需设一次，仍不做属性拦截；
- 关闭静音后若首次被自动播放策略拦下，脚本会提示「点一下页面」，点过之后整段课程不再需要交互。

> 面板自检里的静音项现在只校验「实际状态与你的设置是否一致」，不再强制要求静音。

## 三·E、静音模块已完全移除（v1.1.3）

**结论：脚本不再以任何方式干预音量或静音**，全部交给站点与浏览器。

**为什么移除**（真站实测过程）：

1. 站点会**反复取消静音**——约每 2 秒一次，16 秒内试了 50 多次；
2. 早期版本为了保住静音，在属性层拦截了站点的 `muted` 写入（静音锁）。
   这种持续对抗会让站点每次调音量都被挡回，行为异常，也可能被站点注意到；
3. 随后改为「默认不静音、勾选才设一次」，但仍然是一个与站点对抗的功能点。

现在：

- `CFG.mute` 配置项、`ensureMute` 方法、面板上的「静音」复选框**全部删除**；
- 想安静时用浏览器自带的**「使标签页静音」**（右键标签页），比脚本对抗干净得多；
- 代价：失去了「静音」这条自动播放豁免。首次进入播放页若被自动播放策略拦下，
  脚本会提示「点一下或滚一下页面」，记录到手势后**自动恢复**，之后整段课程不再需要交互。

> 说明：真机浏览器通常已允许本站自动播放，所以多数情况下不会遇到拦截；
> 无头/自动化环境则一律拒绝有声自动播放（这也从反面印证了静音与自动播放的关系）。

### 自动播放拦截图（脚本的处理方式）

```
play() 被拒
   ├─ NotAllowedError（自动播放策略）
   │     → 标记 autoplayBlocked，停止无效重试
   │     → 面板提示一次「点一下页面」
   │     → 记录到任意手势（pointerdown/mousedown/keydown/touchstart/wheel/click）后立即恢复
   └─ 其它错误（AbortError / 媒体被换掉 / 尚不可播）
         → 指数退避重试：0.5s → 1s → 2s → 4s（上限 5s）
         → 不再每 500ms 空转刷屏
```

诊断信息里可用 `autoplayBlocked` / `autoplayBlockCount` / `userGesture` 观察是哪一种。

## 五、已知限制

1. **测验 / 作业 / 考试不会自动完成** —— 脚本会跳过它们，这类内容需要你自己做。
2. **「快进到结尾」默认关闭** —— 部分学校会校验单次播放时长或抽检播放行为，
   开启后虽然更快，但可能被判异常。请自行权衡。
3. **不伪造进度** —— 脚本不会直接调用接口写进度，只保证「视频真的在放」。
4. **真机首次使用建议自查** —— 打开一个视频 → 切到别的标签页十几秒 → 切回来，
   看进度条是否继续走。若没走，把面板「运行日志」最后几行反馈以便定位。
5. **站点改版风险** —— 雨课堂前端会更新（当前逆向版本 `1.2.316`）。
   脚本已尽量使用语义化选择器 + 多级兜底，但仍可能因改版失效。
6. `document.hidden` 被打成不可配置属性后，**同页面其它扩展/脚本也看不到真实可见性**，
   且 `visibilitychange` / `blur` 事件在页面内被吞掉。若某扩展行为异常，
   按 `Alt+S` 停脚本后**刷新页面**才能完全恢复。
7. **建议用「复制诊断信息」反馈问题** —— 面板底部那个按钮会把 URL、是否在 iframe、
   媒体状态、守卫拦截统计、事件拦截自检结果、最近日志一次复制到剪贴板。

## 七、常见问题

**Q：面板没出现？**
确认脚本已启用（篡改猴面板里该项为开），并刷新页面。`@noframes` 意味着
脚本不会注入到 iframe，正常情况下雨课堂主文档即为顶层文档。

**Q：切后台还是暂停了？**
先看面板日志里的「拦截 事件N/暂停M」。若 N=0 说明站点没用可见性检测，
问题在别处；若进度条在走但你觉得慢，注意后台标签页的定时器会被浏览器节流到 1 秒，
属于正常现象。

**Q：想换回 1 倍速正常看？**
面板上点 `1x`，或 `Alt+1`。倍速设置在 `localStorage`（键 `ykt_tool:rate`）里持久化。
